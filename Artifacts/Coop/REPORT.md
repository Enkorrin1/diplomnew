# Кооператив на двоих — первая рабочая основа

Дата: 25.09.2026. Это первый этап реализации, не готовый кооператив всей кампании.

## Запуск

Сборка: `W:/BSUIR/DIPLOOM/Builds/Coop/RogueDriveCoop.exe`.

1. Запустить сборку на обоих компьютерах. Для переноса скопировать всю папку `Builds/Coop`, включая `RogueDriveCoop_Data`, `MonoBleedingEdge` и библиотеки.
2. Первый игрок нажимает «Создать экипаж». Второй вводит IPv4-адрес первого компьютера в локальной сети/VPN и нажимает «Подключиться». `127.0.0.1` подходит только для двух окон на одном компьютере. Используется UDP-порт 7777; доступ приложения через брандмауэр должен быть разрешён в используемой сети.
3. Пешком: WASD, мышь, Shift для бега. Возле машины E — водительское место, F — пассажирское.
4. Водитель: WASD и пробел для торможения. Пассажир: свободный обзор мышью. E — выход, F — смена места; оба действия требуют остановки, новое место должно быть свободным.
5. Esc открывает меню, не останавливая сетевую симуляцию. «Выйти из экипажа» завершает участие; выход хоста завершает соединение клиента.

В редакторе открыть `Assets/Scenes/Coop_Outskirts.unity` и нажать Play. Меню `RogueDrive/Coop/Build Windows prototype` собирает отдельную проверочную Windows-версию. Генератор `Create or refresh prototype scene` пересоздаёт эту сцену из сохранённого окружения Stage1; не использовать поверх несохранённых изменений.

## Реализовано

- Unity Netcode for GameObjects 2.7.0 и Unity Transport 2.6.0, выбранные для Unity 6000.0.
- Максимум два участника, проверка входа на сервере; новые подключения только возле стартовой площадки при остановке машины.
- Хост симулирует машину существующим `GarageDriveOutVehicle`; клиент передаёт команды, а не положение автомобиля. Новый `ExternalInput` исключает смешивание клавиатуры хоста с командами удалённого водителя. По умолчанию одиночное управление сохраняет прежний режим ввода.
- Персонажи двигаются на сервере; положение синхронизируется. Камера и AudioListener принадлежат только локальному игроку. Аватар напарника пешком — временная капсула.
- Два эксклюзивных места. Сервер проверяет отправителя, расстояние, скорость, занятость и свободное место для выхода. Передача водительского места работает в обе стороны между хостом и клиентом.
- Отсутствие команд дольше 0,35 с или отключение водителя включает торможение. Отключение освобождает занятое место. Сессию можно закрыть и создать заново без перезапуска приложения.
- Canvas-меню с адресом, состоянием подключения, выходом и игровыми подсказками; сообщения об отказе в посадке. Неверный адрес и тайм-аут подключения обрабатываются.

- Передача руля клиенту и пассажирского места хосту; движение под управлением клиента.
- Освобождение руля и торможение при отключении клиента.

В логах последнего прогона нет ошибок, исключений и предупреждений. Результаты: `results.txt`. Исходный путь прогона: `latest-test-path.txt`. Просмотрены реальные кадры Windows-сборки: `navigator.png` и `session-menu.png`.

## Границы

- Это отдельная кооперативная сцена с окружением маршрута, а не сетевой режим основной кампании. Общий лут, обслуживание/повреждения, враги, буря, поднятие, ловушки, карта и масштабирование встреч ещё не включены.
- Присоединение на СТО, переходы между сценами, сохранение совместного прогресса, восстановление прерванного заезда и перенос хоста не реализованы. После разрыва можно войти как новый участник, пока машина находится на старте.
- Нет клиентского предсказания движения; задержка LAN приемлема для первого теста, поведение при задержке/потерях VPN ещё нужно измерить. Колёса и звук автомобиля на клиенте требуют отдельной синхронизации представления.
- Проверены отдельные процессы на одном Windows-компьютере; подключение с другого компьютера, реальные VPN и мобильное управление не проверены. Одиночный маршрут целиком повторно не проходился.

## Среда

Установка пакетов первоначально завершалась `ENOSPC`: на C: оставалось около 8 МБ. Настроен `cacheRoot = "W:/UnityPackageCache"` в `C:/Users/egorc/.upmconfig.toml` по официальной документации Unity: https://docs.unity3d.com/6000.0/Documentation/Manual/upm-config-cache.html. Прежний кэш сохранён переносом в `W:/UnityPackageCache/previous-c-cache`; файлы пользователя не удалялись. Это настройка кэша Unity для пользователя, а не часть проекта. Свободного места на C: всё ещё мало.
